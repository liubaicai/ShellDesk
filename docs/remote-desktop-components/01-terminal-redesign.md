## 定位

终端是 ShellDesk 远程桌面的基础能力，不应只是一个 SSH 输出框，而应成为远程工作流的命令执行核心。重新设计时优先考虑长时间使用、可恢复上下文和与其他组件协作。并行排障继续通过远程桌面的多个终端窗口承载；标题栏菜单可把当前窗口向右或向下平铺拆分，但不在单个终端画布内嵌套额外 pane。

## 重新设计目标

- 让单个终端窗口专注于一个稳定、清晰的 SSH shell 会话。
- 让执行长命令、查找历史输出、复制排障片段更顺手。
- 让终端能和文件管理器、命令收藏夹、部署面板、会话录制共享上下文。
- 保持终端本体轻、快、可靠，避免把它做成半个 IDE。

## 功能架构

### 会话层

- 单窗口单会话，窗口标题展示当前会话 title 和连接状态。
- 新建终端窗口支持默认 shell、初始命令和工作目录。
- 标题栏可向右或向下拆分终端工作区；拆分前会通过当前 PTY 探测实时工作目录并传给新会话。实现仍是两个独立的单会话窗口，因此输入、生命周期、关闭确认和后端 PTY 相互隔离；tmux 会话不继承目录，避免把 pane 上下文误当成独立 shell 目录。
- 可在“设置 → 终端”开启工作区记忆。只在当前设备的 `localStorage` 中保存主机作用域的窗口位置、最小化/最大化状态、显式标题、shell、工作目录和 tmux 会话名；绝不保存终端输出、命令历史、运行状态或 `initialCommand`。
- 下次进入同一主机时，保存的窗口只恢复为“已断开”占位，不创建 PTY、不自动重连、不执行命令；每个窗口都必须由用户点击“手动重新连接”。tmux 也只在该点击后重新生成 attach 命令。
- 主窗口“设置 → 终端”可开启“优先使用 tmux”：非 Windows 主机打开首个默认终端时，检测到 `tmux` 后接入或创建 `sd-tmux`；同一虚拟桌面的后续终端窗口保持普通终端，未安装或探测失败时也无感回退为普通终端。
- `tmux` 终端关闭 tmux 底部状态栏，启用 tmux 鼠标模式以让滚轮滚动 pane 历史输出，并把“会话名 · 窗口号:窗口名 · 会话创建时间”写入 ShellDesk 标题栏；仍保留普通终端的标题栏菜单（新建、搜索、清屏、片段、自动跟随和设置），并额外提供会话列表、新建 tmux 与结束当前 tmux 会话。
- tmux 会话列表使用 tmux 会保留的可打印字段分隔符解析名称与窗口、客户端和时间元数据，列表始终展示 `tmux ls` 中的真实会话名，不把整行元数据误作名称。
- “新建 tmux 任务”先通过自定义模态框输入会话名；留空确认时按当前会话列表选择首个可用的 `shelldesk-{序号}`，取消或按 Escape 不创建会话。
- 连接断开时保留终端壳和输出，重连后允许重新创建恢复会话。
- 主窗口可配置终端进程退出后保留窗口、仅成功退出时关闭或任意退出时关闭；无退出状态/信号的意外 SSH 断连不套用该策略，仍保留窗口并自动重连。
- 关闭运行中的终端窗口时给出确认，避免误关长任务。

### 当前后端实现范围

- 远程 SSH 终端不再启动系统 `ssh -tt`，而是通过 russh `channel_open_session`、`request_pty`、`request_shell` / `exec` 直接连接远端 SSHD。
- 同一 ShellDesk 连接上的终端和 SFTP 复用连接级已认证 russh transport，并为每个终端或 SFTP 子系统打开独立 channel；连接关闭时租约统一失效。
- 终端 resize 由 `connection:resize-terminal` 转换为 russh `window_change(columns, rows, 0, 0)`。
- 后端按大小和时间窗口聚合 PTY 输出，渲染层在 xterm 写入回调后确认消费；未确认字节超过高水位时暂停读取，降到低水位后恢复，避免高速输出无限堆积。
- 初始命令、工作目录、自定义 shell 和 su-root 自动化由后端统一生成启动输入或远程 shell command。
- auto-sudo / su-root 密码提示检测基于远端 PTY 输出，密码只写回当前 russh channel，不进入日志。
- 本地模式终端走本机 shell 进程和独立输入/输出管道，不需要 SSH 回环连接。
- 后端已移除 `portable-pty`、`sshpass`、askpass broker 和系统 OpenSSH fallback。

### 交互层

- 选择即复制、右键粘贴、搜索输出、清屏、复制带提示符片段。
- 字体、字号、主题、光标、滚动行为、快捷键偏好。
- 命令中心只在当前应用进程的内存中保留连接内安全单行命令，不跨连接推荐，并排除含常见凭据参数的命令；终端输入区不弹出历史、常用命令或远程路径候选，也不拦截 Tab 和右方向键，命令历史不会写入工作区快照或 vault。
- OSC 8 与自动识别网页链接仅允许 `http` / `https`，拒绝凭据、无主机或超长 URL；点击后先显示自定义确认弹窗，再交给系统浏览器打开。
- 可选的行时间戳使用 xterm marker 在独立左侧 gutter 标记本地接收时间；关键字高亮只处理当前视口及少量缓冲区、限制活动 decoration 数量并按帧预算续跑，不改写远端 PTY 字节流，也不干预全屏备用缓冲区。
- 窗口标题栏展示终端会话状态提示：运行中、退出、断开。
- 长输出采用容量合并、洪泛批次和单轮 10ms 时间预算；全屏备用缓冲区按动画帧合批。最小化窗口或页面隐藏时暂停 xterm 渲染并依靠后端回压维持有界内存，长期隐藏后通过 SerializeAddon 将滚屏压缩为最多 2,000 行的内存快照，并释放 WebGL 与图片资源；恢复可见后继续输出。
- 输出流按队列字节、吞吐率、单块大小和超长行分为正常、繁忙、饱和三级压力；繁忙时暂停装饰性高亮，饱和时同时暂停时间戳。普通缓冲区积压时，Ctrl+C 会优先于陈旧输出进入后端，并确认丢弃的旧显示批次；备用屏幕帧始终保留，避免破坏 TUI 状态。
- 渲染器支持自动、DOM 和 WebGL。自动模式仅为可见 pane 创建 GPU 上下文；Windows Tauri 因 WebView2 兼容性优先使用 DOM，显式 WebGL 仍保留。WebGL context loss 在 60 秒窗口内最多恢复两次，随后对当前终端熔断回退到 DOM。
- 可选 Kitty/SIXEL/iTerm 内联图片默认关闭，限制单图像素、协议载荷和 32 MiB 图片缓存；Kitty CSI-u 键盘协议只在远端 TUI 主动协商后编码增强按键。
- 当前光标行高亮使用 xterm decoration 独立刷新，在选区和备用屏幕中停用；字号支持 Ctrl/Cmd 加减、归零和修饰键滚轮临时缩放，不进入 React 高频状态。
- DEC 2026 同步输出块在用户阅读滚屏时保留光标归位但软化全屏清除，避免 Codex/Claude 等 TUI 把视口强行拉回底部；CSI 3J 是否清除滚屏可单独设置。
- OSC 52 默认完全关闭，可选择仅允许远端写入、读取时逐次确认或显式允许读写；载荷限制为 1 MiB，避免未受限解码、剪贴板投毒和本地内容泄露。
- PTY 的 `TERM` 可在 `xterm-256color`、`xterm-16color`、`xterm` 间选择，并同时作用于 russh PTY 请求与本地 Shell 环境。

### 协作层

- 从文件管理器在当前目录打开终端。
- 从命令收藏夹把命令插入或直接运行。
- 向会话录制上报命令和可选输出摘要。
- 将选中文本发送到便签或复制为排障片段。
- 拖放本地文件/文件夹到远程终端时上传到实时工作目录并插入 shell 安全转义路径；剪贴板图片限制为 10 MiB，暂存文件上传完成后立即清理。本地终端拖放只插入本地路径。
- 选中终端文本后可显式发送给 SD-Agent 解释或生成修复建议；发送前由用户从右键菜单触发，AI 结果不会自动作为命令执行。
- 输入支持 macOS Option+方向键按词跳转、可配置 Shift+Enter、中键行为、软换行复制整理和链接激活修饰键；标题栏工具提供带 Ctrl/Cmd+Enter 执行的多行命令编辑器。
- 标题栏工具菜单可手动开始/停止会话日志，支持纯文本或原始 ANSI，单次最多 10 MiB，默认不录制且不自动持久化。
- 终端设置从平铺开关改为“外观、常用、功能、性能”四组抽屉：常用项直接展示，低频项折叠，并显示依赖关系；关键字高亮改为支持启停、字面量/正则和前景/背景色的结构化规则，非法正则会被忽略，旧逗号关键字会安全迁移。
- 命令中心可搜索当前主机或本次应用运行期间全部连接的安全历史，支持插入、执行、保存为片段和导出 `.sh` / `.ps1`；含凭据参数、多行或过长命令不会进入建议或导出。
- 可临时开启多终端输入广播；密码提示、敏感交互、大段或多行粘贴会阻止广播。广播是当前远程桌面的运行态，不持久化，也不会形成转发环路。
- 备用屏幕可选启用右键菜单，只提供复制/粘贴等不会打断 TUI 键盘协议的操作。

## 交互设计

- 标题栏提供三点终端菜单，承载新建终端窗口、搜索、清屏、自动跟随、滚动到底部和设置。
- 标题栏菜单同时提供向右/向下拆分；空间不足时回退为普通级联新窗口。
- 标题栏菜单可克隆整个终端工作区，逐个保留窗口尺寸、位置和实时工作目录；最多仍受 12 个恢复窗口上限约束。
- 主区域为单一终端画布，优先保证输入焦点和输出阅读稳定。
- 终端画布内不保留额外工具栏和底部状态栏，连接状态统一收敛到窗口标题栏。
- 非常用操作放入菜单，不在终端画布上堆按钮。

## 数据与状态

```ts
interface TerminalSessionState {
  id: string;
  title: string;
  terminalSessionId: string;
  status: 'idle' | 'running' | 'exited' | 'disconnected';
  disconnected: boolean;
  lastExitCode?: number;
}
```

工作区快照使用独立的版本化结构，仅包含恢复所需的非秘密元数据。解析时限制为最多 12 个窗口、验证有限数值 frame，并在显示前按当前桌面和 Dock 范围重新 clamp。

## 能力与集成设计

- SSH shell 会话由 Rust 后端维护，渲染层只消费终端流事件。
- 初始命令和指定工作目录已通过终端启动参数传入。
- 终端输出事件需要可选订阅策略，避免录制与 UI 都无限保存完整输出。
- 不把数据库、文件上传等高层动作塞进终端组件，只保留入口协作。

## 验收标准

- 同一连接可以稳定打开多个终端窗口，各窗口会话互不串写输入。
- 大量输出时 UI 仍可滚动和搜索。
- 后端未确认输出有明确上限，最小化窗口不会持续执行 xterm 写入，恢复显示后输出顺序不变。
- 拆分普通 shell 时新窗口继承触发瞬间的实时目录；命令中心历史和休眠快照不落盘，链接只在安全校验和用户确认后外部打开。
- tmux 会话中的鼠标滚轮进入并滚动 tmux 的 pane 历史，不向 shell 发送上/下方向键而翻动命令历史。
- 连接关闭后终端显示明确状态，不悄悄丢内容。
- 与文件管理器和命令模板的跳转 payload 可用。
- 可从终端直接用实时目录打开文件管理器；开启跟随选项后，已有文件管理器窗口随活动终端目录变化而导航。
- 重新进入主机不会自动启动已保存的 shell；手动重新连接前，后端没有对应终端会话。
- 远程终端不依赖系统 OpenSSH 或本地 PTY 库，resize 能传递到远端 PTY。

## 设计取舍

- 不做完整 shell 历史数据库；命令中心只展示本次应用运行期间观察到的安全单行命令，远端 shell 仍是持久历史的唯一来源。
- 不做单画布内的多标签或嵌套 pane；工作区拆分通过相互独立的终端窗口平铺承载。
- 不做 tmux 替代品，不在终端内承担复杂会话编排。
- 终端仍是基础组件，应比扩展组件更稳定、更少依赖。
