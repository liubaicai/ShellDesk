## 定位

终端是 ShellDesk 远程桌面的基础能力，不应只是一个 SSH 输出框，而应成为远程工作流的命令执行核心。重新设计时优先考虑长时间使用、可恢复上下文和与其他组件协作。并行排障继续通过远程桌面的多个终端窗口承载；标题栏菜单可把当前窗口向右或向下平铺拆分，但不在单个终端画布内嵌套额外 pane。

## 重新设计目标

- 让单个终端窗口专注于一个稳定、清晰的 SSH shell 会话。
- 让执行长命令、查找历史输出、复制排障片段更顺手。
- 让终端能和文件管理器、命令收藏夹、部署面板、会话录制共享上下文。
- 保持终端本体轻、快、可靠，避免把它做成半个 IDE。

## 功能架构

### 会话层

- 单窗口单会话，窗口标题展示当前会话 title 和连接状态。
- 新建终端窗口支持默认 shell、初始命令和工作目录。
- 标题栏可向右或向下拆分终端工作区；实现为两个独立的单会话窗口，因此输入、生命周期、关闭确认和后端 PTY 仍相互隔离。
- 可在“设置 → 终端”开启工作区记忆。只在当前设备的 `localStorage` 中保存主机作用域的窗口位置、最小化/最大化状态、显式标题、shell、工作目录和 tmux 会话名；绝不保存终端输出、命令历史、运行状态或 `initialCommand`。
- 下次进入同一主机时，保存的窗口只恢复为“已断开”占位，不创建 PTY、不自动重连、不执行命令；每个窗口都必须由用户点击“手动重新连接”。tmux 也只在该点击后重新生成 attach 命令。
- 主窗口“设置 → 终端”可开启“优先使用 tmux”：非 Windows 主机打开首个默认终端时，检测到 `tmux` 后接入或创建 `sd-tmux`；同一虚拟桌面的后续终端窗口保持普通终端，未安装或探测失败时也无感回退为普通终端。
- `tmux` 终端关闭 tmux 底部状态栏，启用 tmux 鼠标模式以让滚轮滚动 pane 历史输出，并把“会话名 · 窗口号:窗口名 · 会话创建时间”写入 ShellDesk 标题栏；仍保留普通终端的标题栏菜单（新建、搜索、清屏、片段、自动跟随和设置），并额外提供会话列表、新建 tmux 与结束当前 tmux 会话。
- 连接断开时保留终端壳和输出，重连后允许重新创建恢复会话。
- 主窗口可配置终端进程退出后保留窗口、仅成功退出时关闭或任意退出时关闭；无退出状态/信号的意外 SSH 断连不套用该策略，仍保留窗口并自动重连。
- 关闭运行中的终端窗口时给出确认，避免误关长任务。

### 当前后端实现范围

- 远程 SSH 终端不再启动系统 `ssh -tt`，而是通过 russh `channel_open_session`、`request_pty`、`request_shell` / `exec` 直接连接远端 SSHD。
- 终端 resize 由 `connection:resize-terminal` 转换为 russh `window_change(columns, rows, 0, 0)`。
- 初始命令、工作目录、自定义 shell 和 su-root 自动化由后端统一生成启动输入或远程 shell command。
- auto-sudo / su-root 密码提示检测基于远端 PTY 输出，密码只写回当前 russh channel，不进入日志。
- 本地模式终端走本机 shell 进程和独立输入/输出管道，不需要 SSH 回环连接。
- 后端已移除 `portable-pty`、`sshpass`、askpass broker 和系统 OpenSSH fallback。

### 交互层

- 选择即复制、右键粘贴、搜索输出、清屏、复制带提示符片段。
- 字体、字号、主题、光标、滚动行为、快捷键偏好。
- 可选的行时间戳使用 xterm marker 在独立左侧 gutter 标记本地接收时间；关键字高亮使用 xterm decoration 覆盖普通缓冲区单元格，不改写远端 PTY 字节流，也不干预全屏备用缓冲区。
- 窗口标题栏展示终端会话状态提示：运行中、退出、断开。
- 长输出不阻塞窗口，支持快速滚动到底部和暂停自动跟随。

### 协作层

- 从文件管理器在当前目录打开终端。
- 从命令收藏夹把命令插入或直接运行。
- 向会话录制上报命令和可选输出摘要。
- 将选中文本发送到便签或复制为排障片段。

## 交互设计

- 标题栏提供三点终端菜单，承载新建终端窗口、搜索、清屏、自动跟随、滚动到底部和设置。
- 标题栏菜单同时提供向右/向下拆分；空间不足时回退为普通级联新窗口。
- 主区域为单一终端画布，优先保证输入焦点和输出阅读稳定。
- 终端画布内不保留额外工具栏和底部状态栏，连接状态统一收敛到窗口标题栏。
- 非常用操作放入菜单，不在终端画布上堆按钮。

## 数据与状态

```ts
interface TerminalSessionState {
  id: string;
  title: string;
  terminalSessionId: string;
  status: 'idle' | 'running' | 'exited' | 'disconnected';
  disconnected: boolean;
  lastExitCode?: number;
}
```

工作区快照使用独立的版本化结构，仅包含恢复所需的非秘密元数据。解析时限制为最多 12 个窗口、验证有限数值 frame，并在显示前按当前桌面和 Dock 范围重新 clamp。

## 能力与集成设计

- SSH shell 会话由 Rust 后端维护，渲染层只消费终端流事件。
- 初始命令和指定工作目录已通过终端启动参数传入。
- 终端输出事件需要可选订阅策略，避免录制与 UI 都无限保存完整输出。
- 不把数据库、文件上传等高层动作塞进终端组件，只保留入口协作。

## 验收标准

- 同一连接可以稳定打开多个终端窗口，各窗口会话互不串写输入。
- 大量输出时 UI 仍可滚动和搜索。
- tmux 会话中的鼠标滚轮进入并滚动 tmux 的 pane 历史，不向 shell 发送上/下方向键而翻动命令历史。
- 连接关闭后终端显示明确状态，不悄悄丢内容。
- 与文件管理器和命令模板的跳转 payload 可用。
- 重新进入主机不会自动启动已保存的 shell；手动重新连接前，后端没有对应终端会话。
- 远程终端不依赖系统 OpenSSH 或本地 PTY 库，resize 能传递到远端 PTY。

## 设计取舍

- 首版不做完整 shell 历史数据库，命令历史仍优先依赖远端 shell。
- 不做单画布内的多标签或嵌套 pane；工作区拆分通过相互独立的终端窗口平铺承载。
- 不做 tmux 替代品，不在终端内承担复杂会话编排。
- 终端仍是基础组件，应比扩展组件更稳定、更少依赖。
